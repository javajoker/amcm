从点云、照片与语言
生成 Minecraft 体素对象

输出包含体素空间位置、颜色与材质类型的完整 MC 模型。本文给出可行性判断、分模态技术方案，以及每条参考文献在管线中的具体落点。

总体判断：整体可行，但可行性在不同输入模态上差异极大，必须分阶段推进。下面十节是完整论证。

01 — 结论

三个决定项目形态的判断

这三条不是并列的观察，而是有依赖关系的推论链：风险位置决定投入分配，理论成熟度决定它是工程还是科研，物理上界决定能对用户承诺什么。

风险位置

难点不在重建，在「MC 化」

VGGT、3DGS、TRELLIS.2、SAM2 已把几何与外观获取推到调库可用。真正没有现成方案、必须自研的，是把「占用 + 反照率 + 材质语义 + 法向」映射到「方块 ID + 方块状态」的离散优化层。

理论支撑

是工程问题，不是科研赌注

该层可严格形式化为带成对平滑项的 MRF-MAP 推断，用 α-expansion 求解，度量条件下有 2 倍近似比保证。误差可界、可度量、可回归测试。

物理上界

调色板色域稀疏且有偏

高饱和的青、品红、纯红存在不可消除的色差。应对是抖动 + 色域映射，并把「风格化再现」而非「色彩复刻」写进产品预期。第 1 周必须量化它。

02 — 物理上界

Minecraft 的颜色，你只有这些

这是项目唯一无法通过工程手段消除的约束，所以放在最前面。下面是可用作颜色源的方块的真实色值，按来源分成两组 —— 分组本身就是结论。

自然与建材方块 · 有纹理

石、木、土、砂、矿物。纹理丰富，但集中在低饱和的灰、棕、绿。这是 MC 色域的主体。

染色方块 · 羊毛 / 混凝土 / 陶瓦

16 色 × 三个系列。这里才有高饱和度 —— 但它们几乎没有纹理，是平色块。

这张图的真正结论不是「颜色少」，而是「饱和度与纹理不可兼得」。 高饱和只来自染色系列，而染色系列几乎是平色；有纹理的自然方块几乎都是低饱和。所以调色板匹配不能只比平均色 —— 必须同时匹配纹理频率能量，否则会把大片平墙配成花岗岩，或把细节丰富的表面配成一片死板的混凝土。
实验 E1 · 第 1 周 · 最高优先级。 从游戏资源提取全部「方块 × 面」的 Lab 平均色与方差，计算调色板在 sRGB 内的最大最近邻距离场，输出一张「哪些颜色 MC 表达不了」的热力图。预期低饱和区 ΔE₀₀ < 5，高饱和区 ΔE₀₀ > 20。这个数字会直接改写产品文案与验收标准，所以必须先于一切模型工作完成。

03 — 架构

三层分解，与随之而来的投入分配

全部输入模态共享同一后端，差异只在于前端如何得到「几何 + 外观 + 语义」三元组。这个分层直接决定了人力该往哪放 —— 任何把主要精力花在「选哪个 3D 生成模型」上的规划都是错配的。

L1

几何层 — 复用为主

任意输入 → 占用场 + 表面法向 + 亚体素残差。VGGT / COLMAP / 3DGS / TRELLIS.2 / 广义缠绕数体素化。TRL 8–9，基本是集成工作。

15%
L2

外观层 — 复用加调优

去光照取反照率（RGB↔X），材质语义分割（SAM2 + DMS/MatSeg + 开放词表）。TRL 6–7，材质分类需要微调，去光照是质量分水岭。

30%
L3

Blockification — 必须自研，全部差异化价值所在

方块调色板构建 → 一元代价 → MRF 联合标注 → 亚体素几何拟合 → 物理合法性修复 → 格式导出。无现成方案。

55%

中间表示是架构的枢纽

它必须先于任何模态管线定义清楚，否则每接一个新输入都会污染核心层。三个非常规的设计决定：

字段形状为什么这样设计
albedo(Nv, 6, 3)逐面存储，不是逐体素。MC 方块各向异性 —— 草方块顶绿侧土。逐体素平均会丢掉这个关键区分，也丢掉「不同面被不同视角看到、置信度不同」的信息。
residual(Nv,)体素化通常丢弃这个量。但真实表面到体素中心的有符号偏移，正是楼梯/台阶等亚体素原语的驱动信号。丢了就再也拿不回来。
albedo_conf(Nv, 6)显式记录未观测区域。物体背面、内部、遮挡区没有观测，必须走补全或纯语义推断，不能当成黑色处理。

04 — 核心算法

L3 求解什么

把一个模糊的「AI 生成」需求，转化为一个有五十年文献支撑的组合优化问题 —— 这是本项目最重要的可行性依据。求方块分配 b: V → B × S，最小化：

E(b) = Σv [ λ_c · D_color( a_v , c(b_v, n_v) ) ← 颜色项：逐面 ΔE₀₀，只惩罚看得见的面 + λ_m · ( −log p_v( mat(b_v) ) ) ← 材质语义项：分割模型给的后验 + λ_t · | freq(a_v) − freq(b_v) | ← 纹理频率项：便宜且效果明显 + λ_g · D_geom( r_v , geom(b_v) ) ] ← 亚体素几何项：楼梯/台阶拟合 + Σ(u,v)∈N λ_s · ψ( b_u , b_v ) ← 成对项：方块共现先验，抗椒盐噪声 + λ_p · Φ_physics(b) + λ_b · Ψ_budget(b) ← 建议做后处理 pass，不入能量

三条让它真正可解的工程判断

A

一元项不是瓶颈

|V|≈4×10⁵、|B|≈400 时约 1.6×10⁸ 次查表，GPU 上几百毫秒。真正需要控制规模的是成对项 —— 只在表面体素上做 MRF，内部直接填最便宜的结构方块，规模降一个量级；再按 32³ 分块、块间重叠 4 体素做边界一致化。N=256 预期 30–120 秒。

B

成对项 ψ 从真实建筑语料统计得来

方块共现频率来自 3D-Craft、GDMC 参赛作品、社区 schematic。这是把「人类建筑师的审美」注入系统的最低成本途径 —— 比训练任何模型都便宜，效果立竿见影。v2 可换成在 MC 语料上训练的稀疏体素离散扩散先验：方块 ID 天然是离散 token，与掩码 token 建模的假设完美契合。

C

3D 抖动必须用蓝噪声，不能用 Floyd–Steinberg

2D map art 普遍用 FS 误差扩散，直接搬到 3D 是错的：FS 的误差沿扫描方向传播，产生蠕虫状方向性伪影。2D 观察方向固定时不显眼，但 3D 对象可任意旋转，某些角度会突然刺眼。改用 void-and-cluster 生成的 3D 蓝噪声阈值场：各向同性、可平铺、O(1) 查表、天然可复现。

亚体素几何拟合是最值得投入的差异化点。 楼梯（4 facing × 2 half × 5 shape）、台阶、地毯（1/16）、雪层（8 级 1/8 步进）能在不提高体素分辨率的前提下把有效几何精度提升约一档。屋顶、圆柱、球面的观感提升显著。这是 MC 特有的杠杆，也是与通用体素工具拉开差距的地方 —— 它最能体现「懂 Minecraft」。

05 — 本质困难

五个绕不过去的问题

01

调色板色域缺口 不可消除

见第 02 节。只能缓解：3D 蓝噪声抖动扩展感知色域、输入侧做色域映射保序不保绝对值、产品定位为风格化再现。

02

尺度歧义 需用户介入

单图与纯 SfM 都没有绝对尺度，而「一个方块 = 多少米」决定一切。若强行令 1 block = 1 m，10 米高的房子只有 10 层体素，门窗细节全丢。必须把 voxels_per_meter 作为一等参数暴露，并提供三种定标途径：用户直接给尺寸、场景已知物体反推、metric depth 模型或 LiDAR。

03

光照烘焙污染 最易低估

直接用照片像素色匹配方块，阴影会被烤进方块选择 —— 同一面白墙被切成明暗两种方块，形成难看的色块分界。必须先做内在图像分解取反照率。这一步的投入产出比在整条管线里最高，是「AI 玩具」和「人类建筑师作品」的分界线。

04

语义→方块的知识缺口 核心数据资产

「这是砖」→ 该用 bricks 还是 red_nether_bricks 还是 granite？这是一张需要人工精修的领域知识表（约 30 类 × 每类 5–30 个候选块），没有模型能凭空替代。应独立立项、版本化、支持按风格切换多套映射表 —— 这是用户可感知价值最高而技术成本最低的功能点。

05

LLM 在长程 3D 坐标上一致性差 改走 DSL

直接让 LLM 输出体素坐标，超过几百块后会出现对称性破缺、坐标漂移、结构不闭合。先行工作 T2BM 引入「层间表示 + 修复」正是在打这个补丁。结论：语言模态不应走「LLM 直吐体素」，应走「LLM 输出建造程序」 —— 程序天然保证对称、重复、参数化，且可读可编辑可重跑。

06 — 输入模态

八条管线，与一个反直觉的优先级

最该先做的不是传播性最强的「照片 → MC」，而是「现成 3D 资产 → MC」。

模态质量风险阶段关键技术与要点
D1 · 现成 3D 资产OBJ / glTF + 贴图 ★★★★★低MVP 首选 几何、外观、语义三项全部已知，L1/L2 噪声为零 —— 能让 L3 在干净条件下独立调优，并从 Objaverse 批量构造带真值的回归测试集。跳过这步直接做照片，等于在噪声输入上调试未验证的核心算法。
A · 点云 + 全景全彩图 ★★★★★中 · 配准v1 Poisson + 广义缠绕数实体体素化（比表面体素化稳健）；逐面投影烘焙用加权中位数而非平均，自动排除高光、行人、玻璃反射。全景须先投影到 cubemap / tangent patches 再送 2D 模型，否则 ERP 极区畸变会显著拉低精度。MVP 建议只支持同源采集设备。
C1 · 多视角照片 / 视频 ★★★★★中v1 VGGT 出位姿（前馈秒级、无需内参，解决 COLMAP 在弱纹理少视角下失败）→ 3DGS 精化外观 → 2DGS / SuGaR 提表面 → 体素化。COLMAP 作稳健兜底。
C2 · 单张照片 ★★★★★中v1 可能是全项目质量／成本比最高的一条路径：TRELLIS 系的内部表示本身就是稀疏体素（SLAT / O-Voxel），可直接在其体素结构上做 L3，跳过 mesh↔voxel 往返，省掉两次量化误差。局限须向用户明示：背面是幻觉、无绝对尺度。
B · 自然语言 ★★★★★中高v1 LLM 输出建造 DSL（几何体 / 建筑构件 / 变换 / 布尔 / 材质刷 / 约束），配 Verifier 闭环：几何闭合、门可通行、采光比、物理支撑、预算、CLIP 语义符合度。失败时回灌结构化错误而非自然语言抱怨，通常 2–3 轮收敛。
D3 · CAD / BIM (IFC) ★★★★★低v2 映射质量最高的输入模态。几何精确无重建误差；材质语义天然存在（IfcMaterial）—— 语义是真值而非预测；楼层构件层级可直接映射分层建造。
D4 · GIS / DEM / OSM ★★★★★低v2 DEM → 地形高度场；OSM footprint + levels → 体量拉伸；landuse 标签 → 材质类。工程成熟度高、风险低、传播性强，已有 Arnis / WorldPainter 等成熟先例。
D5 · 手机 LiDAR / RGB-D ★★★★★低v1 是模态 A 的最佳采集手段：直接给米制尺度点云 + 已对齐彩色，免去尺度标定。配套 iOS 采集 App 是降低使用门槛最有效的手段。

另有 D2 手绘三视图（★★☆☆☆，v2）、D6 低分辨率体素超分（★★★☆☆，v2）。D7 视频 → 动态 4D 建议排除 —— MC 无原生动画体素支持，需命令方块 hack，投入产出比差。

资源

09 — 文献

时间有限就读这八篇

完整索引按 16 个主题分类，每条都标注了在管线中的具体落点。这里是覆盖 80% 关键决策的最小集合。

01

Fast Approximate Energy Minimization via Graph Cuts · Boykov, Veksler, Zabih · PAMI 2001

α-expansion 的原始文献，L3 求解器的核心。度量条件下有 2 倍近似比保证 —— 这是「工程问题而非科研赌注」这个判断的直接依据。

02

What Energy Functions Can Be Minimized via Graph Cuts? · Kolmogorov & Zabih · PAMI 2004

判定哪些能量函数可用图割求解。设计成对项 ψ 时的必读约束条件 —— 决定了共现先验能写成什么形式。

03

TRELLIS: Structured 3D Latents · CVPR 2025 Spotlight · 及后继 TRELLIS.2

本项目最关键的外部依赖。SLAT / O-Voxel 表示本身就是稀疏体素 —— 那条「直接在其体素结构上做 L3、跳过 mesh 往返」的捷径就出自这里。TRELLIS.2 还输出完整 PBR 材质。

04

ObjToSchematic · 开源工程

最接近的先行工程实现：网格 → MC 方块，含体素化算法选择与调色板匹配。建议精读其颜色匹配与抖动部分再动手写自己的版本。

05

RGB↔X: Material- and Lighting-aware Diffusion · SIGGRAPH 2024

去光照首选，一次输出 albedo / normal / roughness / metallic / irradiance。对应第 05 节的第三个困难 —— 质量分水岭就在这一步。

06

Robust Inside-Outside Segmentation using Generalized Winding Numbers · SIGGRAPH 2013

稳健实体体素化的理论基础。对非水密、带噪、自相交的网格与点云仍能正确判内外 —— 而这正是真实重建数据的常态。

07

The Void-and-Cluster Method for Dither Array Generation · Ulichney · SPIE 1993

3D 各向同性蓝噪声抖动的算法来源。对应第 04 节的判断 C —— 为什么不能直接用 Floyd–Steinberg。

08

3D Building Generation in Minecraft via LLMs (T2BM) · IEEE CoG 2024

语言模态最直接的先行工作。重点看它的「层间表示 + 修复」机制 —— 那正是「LLM 直吐体素会失败」的实证，支撑改走 DSL 路线。

其余主题：Minecraft 格式规范与工程库（Sponge Schematic v3 / Amulet-Core / litemapy）、多视角重建与 SLAM（VGGT / DUSt3R / MASt3R / COLMAP）、辐射场（3DGS / 2DGS / SuGaR / Neuralangelo）、全景深度、开放词表分割、材质识别数据集（DMS / MatSeg / MINC）、稀疏体素骨干、离散扩散、色彩科学、LLM 程序化生成、数据集、评测方法。索引维护约定：新增条目必须填写「用在哪」，被证伪的方案不删除而是移入「已排除方案」并注明原因，避免团队重复踩坑。

10 — 立即行动

三件现在就能开始的事

都不依赖任何模型，可以并行启动。

实验 E1

调色板色域量化

提取全部「方块 × 面」的 Lab 平均色，计算 MC 色域在 sRGB 内的最大最近邻距离场，输出「哪些颜色表达不了」的热力图。这个结论会直接改写产品承诺与验收标准，所以必须最先做。

链路验证

打通导出到游戏

手工构造一个体素数组 → 导出 .litematic → 在真实游戏中成功放置。这条链路不通，其余都是空谈。默认导出 .litematic（无大小限制），原版结构方块有 48³ 硬上限。

迭代基建

渲染验证回路

自动把输出用 Chunky 渲染成图，与参考视图比对 LPIPS / DISTS。没有它就无法迭代 —— 而且 GDMC 的研究已表明自动 PCG 指标与人类评价相关性有限，所以人类评分也不能省。
