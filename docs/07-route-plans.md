## 0. 所有路线的共同约定

每条路线**只做一件事：产出 `VoxelIR`**（架构规则 AR-1）。之后统一走：

```python
ir     = <route>_to_ir(inputs, cfg)      # ← 路线的全部职责到此为止
result = BlockifyPipeline(cfg).run(ir)   # ← 公共 L3，八条路线共用
export(result, out_path)                 # ← 公共导出
```

因此每条路线的研发计划都围绕同一个问题展开：**这条路线如何填满 IR 的哪些字段，缺失的字段如何降级。**

### 路线对 IR 字段的填充能力

| 路线 | coords | normal | residual | albedo | conf | freq | mat_logits | instance |
|---|---|---|---|---|---|---|---|---|
| D1 资产 | ✅ | ✅ | ✅ | ✅ | ✅满 | ✅ | ✅ 材质名 | ✅ |
| C2 单图 | ✅ | ✅ | ✅ | ✅ | ⚠️背面低 | ✅ | ⚠️ 预测 | ✅ |
| C1 照片 | ✅ | ✅ | ✅ | ✅ | ⚠️不均 | ✅ | ⚠️ 预测 | ✅ |
| A 点云+全景 | ✅ | ✅ | ✅ | ✅ | ⚠️不均 | ✅ | ⚠️ 预测 | ⚠️ |
| B 语言 DSL | ✅ | ✅ | ✅ | ➖ | ➖ | ➖ | ✅ **直接指定** | ✅ |
| D3 CAD/BIM | ✅ | ✅ | ✅ | ⚠️部分 | ✅ | ➖ | ✅ **真值** | ✅ |
| D4 GIS | ✅ | ⚠️ | ➖ | ⚠️影像 | ⚠️ | ➖ | ✅ 标签 | ✅ |
| D6 体素超分 | ✅ | ✅ | ✅ | ✅ | ✅ | ➖ | ✅ 继承 | ⚠️ |

✅ 可靠 · ⚠️ 部分/有噪 · ➖ 不产出（走降级）

> **这张表是分路线计划的索引。** 它一眼说明了为什么资产路线适合做 MVP（唯一一行全绿），也说明了语言路线和 CAD 路线为什么不需要外观管线——它们直接给出材质语义，颜色由映射表决定。

## 路线 D1 · 现成 3D 资产 【MVP】

**目标形态**：OBJ / glTF / FBX + 贴图 → MC 结构

### 依赖

| 类型 | 内容 |
|---|---|
| 公共库 | `core` `palette` `color` `geom.voxelize` `geom.residual` `blockify` `io` |
| 外部 | trimesh / pygltflib（轻量，**无重模型依赖**） |
| 数据 | Objaverse 采样子集 |
| 前置阶段 | Phase 0 全部门禁 |

### 里程碑

| # | 内容 | 周期 |
|---|---|---|
| D1-M1 | 网格加载 + 实体体素化 + 残差 | 1 周 |
| D1-M2 | 逐面 UV 采样 → albedo（glTF baseColor ≈ albedo，**无需去光照**） | 1 周 |
| D1-M3 | 材质名 → 材质类归一化（规则匹配 + LLM 兜底） | 0.5 周 |
| D1-M4 | 端到端打通 + CLI | 0.5 周 |
| D1-M5 | Objaverse 200 回归集 + 基线跑分 | 1 周 |

### 验收

- [ ] 200 对象批量转换成功率 ≥ 98%
- [ ] Voxel IoU ≥ 0.90（对水密真值）
- [ ] 端到端 N=128 < 30 s
- [ ] 材质类归一化准确率 ≥ 80%（人工抽检 50 个）
- [ ] 转换结果在游戏内加载放置成功（抽检 10 个）

### 专属风险

| 风险 | 缓解 |
|---|---|
| Objaverse 资产质量参差（非水密、法向翻转、贴图缺失） | 广义缠绕数天然稳健；建立"困难资产"子集专门测试 |
| 材质名混乱（`Material.001`、`mat_0`） | 规则匹配失败时回退到纯颜色匹配，并在报告中标注 |
| PBR 的 baseColor 未必等于 albedo（有些资产烤了 AO） | 检测异常暗区并警告；提供 `--assume-baked-ao` 开关 |

> **本路线的战略价值不在它本身，而在它是 L3 的调试台架。** 排期上任何时候都不应为了赶其他路线而牺牲它的回归集建设。

## 路线 C2 · 单张照片 【最高性价比】

**目标形态**：一张照片 → MC 结构

### 依赖

| 类型 | 内容 |
|---|---|
| 公共库 | 同 D1，加 `semantic` |
| 适配器 | **`mcvox-adapters-trellis`**（TRELLIS.2 优先，支持 O-Voxel） |
| 前置阶段 | Phase 2（需 L3 已成熟才能体现质量） |

### 里程碑

| # | 内容 | 周期 |
|---|---|---|
| C2-M1 | TRELLIS.2 适配器封装，实现 `Generative3DAdapter` | 1 周 |
| C2-M2 | **★ 稀疏体素捷径**：`native_sparse_voxels()` 直取 O-Voxel，跳过 mesh 往返 | 1 周 |
| C2-M3 | PBR 材质 → `mat_logits` 映射（TRELLIS.2 输出含 PBR） | 0.5 周 |
| C2-M4 | 尺度标定 UI/参数（用户指定尺寸为默认） | 0.5 周 |

### 验收

- [ ] 端到端 < 90 s（单卡 24 GB）
- [ ] 峰值显存 ≤ 22 GB
- [ ] **捷径路径与 mesh 往返路径的质量对比报告**（量化省下的量化误差）
- [ ] 背面幻觉与无尺度两个局限在 CLI/UI 中明确提示用户

### 专属风险

| 风险 | 缓解 |
|---|---|
| `native_sparse_voxels()` 的体素分辨率与目标 `voxels_per_meter` 不匹配 | 需要重采样。**M2 必须先验证这一点**，否则捷径不成立 |
| TRELLIS.2 的 O-Voxel 结构未公开稳定 API | 适配器封装隔离；准备 mesh 往返作为回退路径 |
| 背面是幻觉，用户预期错配 | 产品文案 + 结果页明确标注；提供"只导出可见面"选项 |

> **M2 是本路线的成败点，也是全项目质量/成本比最高的一次押注。** 建议它作为一个独立的一周探针任务先做，验证通过再投入其余里程碑。

## 路线 B · 自然语言 【独立性最强】

**目标形态**：文字描述 → MC 结构

### 依赖

| 类型 | 内容 |
|---|---|
| 公共库 | `core` `blockify` `io`（**不需要 `appearance`**——材质直接指定） |
| 外部 | LLM API；无需 3D 重建依赖 |
| 前置阶段 | Phase 2 |

**本路线与其他路线共享依赖最少，是并行开发的最佳候选。**

### 里程碑

| # | 内容 | 周期 |
|---|---|---|
| B-M1 | 建造 DSL 设计与解释器（原语见[方案 §5.B1](02-solutions.md)） | 1.5 周 |
| B-M2 | DSL → `VoxelIR`（几何 + `mat_logits` 直接指定，`albedo` 走降级） | 0.5 周 |
| B-M3 | **Verifier**：几何闭合 / 可达性 / 采光 / 物理 / 预算 / CLIP 符合度 | 1.5 周 |
| B-M4 | LLM ↔ Verifier 闭环，结构化错误回灌 | 1 周 |
| B-M5 | 提示词工程 + 少样本示例库 | 0.5 周 |

### 验收

- [ ] 20 条测试描述中 ≥16 条在 3 轮内通过 Verifier
- [ ] 生成的 DSL 程序**人类可读可编辑**，改一个参数能得到预期变化
- [ ] 对称结构严格对称（这是走 DSL 路线的全部理由，必须验证）
- [ ] CLIP-score 达标（阈值待 B-M3 后标定）

### 专属风险

| 风险 | 缓解 |
|---|---|
| DSL 原语覆盖不足，LLM 反复撞墙 | M1 先用 20 条真实描述反推需要哪些原语，**不要凭空设计** |
| Verifier 误报导致无限循环 | 硬性轮次上限；超限则输出最后一版 + 问题清单，而非失败 |
| LLM API 成本/延迟 | 缓存相同描述；简单结构走模板不走 LLM |
| DSL 表达力与易用性冲突 | 分两层：LLM 面向的完整 DSL + 用户面向的简化参数 |

> **B-M1 的做法很关键**：先收集 20 条真实用户会写的描述，从中反推需要的原语，而不是先设计一套"完备"的 DSL。后者几乎必然设计出用不上的原语，同时漏掉高频需求。

## 路线 C1 · 多视角照片 / 视频

**目标形态**：一组照片或一段视频 → MC 结构

### 依赖

| 类型 | 内容 |
|---|---|
| 公共库 | 全部，含 `appearance` `semantic` |
| 适配器 | VGGT（主）· COLMAP（兜底）· 3DGS/2DGS · SAM2 · RGB↔X |
| 前置阶段 | Phase 2 + C2 完成（复用部分适配器） |

**这是依赖最重的一条路线**，也是 `appearance` 与 `semantic` 模块的主要驱动者。

### 里程碑

| # | 内容 | 周期 |
|---|---|---|
| C1-M1 | VGGT 适配器 + COLMAP 兜底回退逻辑 | 1 周 |
| C1-M2 | 3DGS 精化 + 2DGS/SuGaR 表面提取 → 网格 | 1 周 |
| C1-M3 | **`appearance.bake`** 逐面投影烘焙（加权中位数抗高光） | 1 周 |
| C1-M4 | **`appearance.delight`** RGB↔X 去光照集成 | 0.5 周 |
| C1-M5 | `semantic`：SAM2 + 开放词表分类 + 多视角投票融合 | 1.5 周 |
| C1-M6 | 尺度标定三途径（用户给定 / 已知物体 / metric depth） | 0.5 周 |

### 验收

- [ ] 40 张照片端到端 < 15 min
- [ ] **去光照消融实验**：对比开/关，验证同色墙面不被切成明暗两种方块
- [ ] SfM 失败时自动回退且记入 provenance
- [ ] 真实场景测试集（≥10 组自采）人工评分达标

### 专属风险

| 风险 | 缓解 |
|---|---|
| 弱纹理/少视角下重建失败 | VGGT 前馈本就为此而生；COLMAP 兜底；失败给出**拍摄建议**而非报错 |
| 去光照效果不稳定 | M4 做消融实验量化收益；效果不佳时提供关闭开关，但默认开启 |
| 多视角语义不一致 | 用 SAM2 的视频一致性；或引入 Gaussian Grouping |
| 户外场景光照变化剧烈 | 加权中位数已能抗部分；必要时按曝光归一化 |

> **C1-M3 与 C1-M4 是本路线的质量决定项**，也是唯二会被点云路线复用的模块。它们的实现质量直接决定 A 路线的上限，值得多投入。

## 路线 A · 点云（白模）+ 全景全彩图

**目标形态**：点云 + 全景图 → MC 结构

### 依赖

| 类型 | 内容 |
|---|---|
| 公共库 | 全部；**重度复用 C1-M3 的烘焙实现** |
| 适配器 | SAM2 · RGB↔X · 全景深度（可选）· MASt3R（异源配准兜底） |
| 外部 | Open3D |
| 前置阶段 | **C1 完成**（否则烘焙要写两遍） |

### 里程碑

| # | 内容 | 周期 |
|---|---|---|
| A-M1 | 点云预处理：去噪 / 法向估计 / Poisson 重建 | 1 周 |
| A-M2 | **`appearance.panorama`** ERP ↔ cubemap / tangent 投影 | 1 周 |
| A-M3 | 同源采集的外参直用 + 投影烘焙（复用 C1-M3） | 0.5 周 |
| A-M4 | 全景上的分割与材质分类（在无畸变切平面上跑） | 1 周 |
| A-M5 | 异源配准兜底（渲染-匹配 + 手动标点） | 1.5 周 · **可延后** |

### 验收

- [ ] Matterport3D 样本端到端跑通
- [ ] 实体体素化对带噪点云无空洞
- [ ] **ERP 直跑 vs 切平面跑的分割精度对比报告**（验证 M2 的必要性）
- [ ] 未观测面的补全行为符合预期，不出现黑洞

### 专属风险

| 风险 | 缓解 |
|---|---|
| **异源配准失败**（本路线最大风险） | **MVP 只支持同源采集设备**；A-M5 延后，先交付同源版本 |
| ERP 极区畸变拉低 2D 模型精度 | A-M2 强制走切平面；用对比报告证明必要性 |
| 点云密度不均导致体素化空洞 | 实体体素化 + 形态学闭运算；密度检测并警告 |
| 全景中的动态物体（行人）污染烘焙 | 加权中位数天然抗离群；必要时加人物分割剔除 |

> **排期建议：把 A-M5 异源配准砍出主线。** 它是本路线失败模式最多、调试成本最高的部分，而同源采集（Matterport / iPhone LiDAR / BLK360）已覆盖绝大多数真实使用场景。先交付同源版本拿到反馈，再决定是否值得做异源。

## 路线 D5 · 手机 LiDAR / RGB-D 扫描

**定位：不是独立路线，而是路线 A 的最佳采集前端。**

- 直接给出**米制尺度**点云 + 已对齐彩色 → 免去尺度标定
- 外参已知 → 免去配准（路线 A 的最大风险直接消失）
- 工作量：ARKit/ARCore 数据格式解析 + 配套采集 App（约 2 周 + App 另计）

**这是降低用户使用门槛最有效的一步棋**，投入产出比高于异源配准。建议在路线 A 同源版本交付后立即做。

## 路线 D3 · CAD / BIM (IFC)

**目标形态**：IFC 模型 → MC 结构 · **映射质量最高的输入模态**

### 依赖

`core` `geom` `blockify` `io` + IfcOpenShell。**不需要 `appearance` 与 `semantic`**——材质是真值。

### 里程碑

| # | 内容 | 周期 |
|---|---|---|
| D3-M1 | IfcOpenShell 解析 → B-rep → 网格 | 1 周 |
| D3-M2 | `IfcMaterial` / 构件类型 → 材质类（真值映射） | 0.5 周 |
| D3-M3 | 楼层/构件层级 → `instance_id` + 分层建造顺序 | 0.5 周 |
| D3-M4 | 大尺度分块导出（建筑常超 48³ 甚多） | 1 周 |

### 验收

- [ ] 标准 IFC 样例文件端到端跑通
- [ ] 材质类映射准确率 ≥ 95%（有真值，应显著高于预测路线）
- [ ] 建筑级尺度（>256³）可分块导出并正确拼接

### 专属风险

| 风险 | 缓解 |
|---|---|
| IFC 版本与厂商方言差异大 | 限定支持 IFC4；建立样例文件测试集 |
| 建筑尺度导致体素数爆炸 | 分块流式处理；提供 LOD 参数 |

## 路线 D4 · GIS / DEM / OSM

**目标形态**：地理数据 → MC 世界尺度地形与建筑

### 依赖

`core` `blockify` `io` + rasterio / GDAL / osmnx。已有成熟先例（Arnis、WorldPainter）可参考。

### 里程碑

| # | 内容 | 周期 |
|---|---|---|
| D4-M1 | DEM → 地形高度场 → 体素 | 1 周 |
| D4-M2 | OSM footprint + levels → 建筑体量拉伸 | 1 周 |
| D4-M3 | landuse/natural 标签 → 材质类 | 0.5 周 |
| D4-M4 | 卫星影像 → 地表颜色（可选） | 1 周 |
| D4-M5 | 直接写 MC 世界（Amulet-Core），而非 schematic | 1 周 |

### 验收

- [ ] 1 km² 区域端到端生成并可在游戏中漫游
- [ ] 地形与建筑对齐正确，无浮空/陷地
- [ ] 生成的世界可正常加载，无区块损坏

### 专属风险

| 风险 | 缓解 |
|---|---|
| 尺度巨大，内存与耗时爆炸 | 分区块流式生成；这条路线**必须**用 Amulet 直写世界 |
| MC 世界高度限制（-64~320） | DEM 高程需压缩映射；提供垂直缩放参数 |
| 已有成熟工具（Arnis），差异化不足 | 差异在材质语义质量与影像着色；**若差异不足应考虑不做** |

> D4 是唯一一条**需要先论证"为什么不用现成工具"** 的路线。建议 Phase 4 前重新评估其优先级。

## 附：路线优先级与排期建议

| 优先级 | 路线 | 理由 |
|---|---|---|
| **1** | D1 资产 | L3 的调试台架，MVP |
| **2** | C2 单图 | 质量/成本比最高；捷径押注 |
| **3** | B 语言 | 独立性最强，可完全并行；传播性好 |
| **4** | C1 照片 | 依赖最重，但用户需求最直观 |
| **5** | A 点云（同源） | 复用 C1；面向专业采集场景 |
| **6** | D5 RGB-D 采集端 | 低成本高杠杆，降低使用门槛 |
| **7** | D3 CAD/BIM | 垂直场景高价值，映射质量最高 |
| **8** | D4 GIS | 需先论证差异化 |
| **9** | D6 体素超分 | 依赖 F-26，不确定性最高 |

**若只能做三条**：D1 + C2 + B。这个组合覆盖了"已有模型"、"一张图"、"一句话"三种最低门槛的入口，且相互依赖最少。
